## 4. Phase 0: 確定発話を失わない取り込み制御

### 4.1 Lane 設計

現行 `SpeechSegmenter` は final 相当の発話セグメントのみを出す。したがって Phase 0 では次の2レーンで足りる。

| Lane | 内容 | 破棄方針 |
|------|------|----------|
| Audio Frame（将来） | 生フレーム連続ストリーム | max_age 超過で破棄可。Phase 1 持続ランタイム導入時に本格使用 |
| Final | 確定発話セグメント（現行 queue の中身） | soft_limit 内では破棄禁止。hard_limit / max_age のみ明示破棄 |

Partial Lane は Phase 2（interim 字幕送出）まで保留する。

### 4.2 SegmentIngress（新規シーム）

**配置:** `backend/app/webrtc/ingress.py`（純ロジック、I/O・rtc 非依存）

**責務:** lane 判定・soft/hard limit・max_age・overload 判定・メトリクス更新。  
`LiveKitAgent._enqueue_segment` のインライン破棄ロジックを置換する。

```python
# プロトタイプ由来の決定形状（実装時の契約）
@dataclass(frozen=True)
class IngressDecision:
    action: Literal["accept", "accept_degraded", "drop_aged", "drop_hard"]
    depth: int
    age_ms: float | None
    reason: str

class SegmentIngress:
    def __init__(
        self,
        *,
        soft_limit: int = 8,
        hard_limit: int = 64,
        max_age_ms: int = 30_000,
    ) -> None: ...

    def decide_enqueue(self, *, depth: int, oldest_age_ms: float | None) -> IngressDecision: ...
    def record_drop(self, reason: str) -> None: ...
    def snapshot(self) -> dict: ...  # depth, age_p95, final_dropped, overload
```

#### soft / hard / max_age の意味

| しきい値 | 既定 | 挙動 |
|----------|------|------|
| `soft_limit` | 8 | **破棄しない**。`overload_degraded` を発火し、聞く主線（Mode A / hearing）を一時停止。読む主線のみ継続し、1発話あたりコストを下げてキューを自然回復させる |
| `hard_limit` | 64（話者あたり目安 約16MB） | メモリ保護のため最古を破棄。必ず `final_dropped` カウンタ + error ログ。黙って捨てない |
| `max_age_ms` | 30000 | 字幕価値が薄い古い Final を破棄可。同様に計上 |

**「final 字幕欠落 0 件」の定義:** soft_limit 運用範囲（通常過負荷）での保証。hard_limit / max_age による破棄は境界条件として明示し、観測可能であること。

### 4.3 過負荷時の縮退順序

```text
1. （Phase 2 以降）partial / interim 字幕を停止
2. Mode A（聞く主線・翻訳音声）を停止  ← soft_limit 到達時
3. Mode B（読む主線・確定字幕・記録）を継続
4. overload_degraded イベントを DataChannel(topic=qos) で通知
5. ログ・メトリクスで管理者向けに可視化
```

配線:

- soft 超過フラグを `HybridOrchestrator.orchestrate` の `s2s_available` 入力へ反映（既存の hearing 縮退経路 `orchestrator.py` L225-228, `mode_router.py` L93-97 を再利用）。
- イベントは既存 `OutputSink.deliver_event`（`sink.py` L85-87）経由。

### 4.4 Queue depth / age メトリクス

| 指標 | 計測点 | 公開先 |
|------|--------|--------|
| `queue_depth` | 話者別 queue の `qsize()` | Ingress snapshot / ログ /（任意）qos イベント |
| `queue_age_ms` | enqueue 時刻からの経過 | 同上。dequeue 時に oldest を更新 |
| `final_dropped` | hard / aged 破棄回数 | カウンタ。会議終了時の観測に含めてよい |
| `overload` | soft 超過中か | bool。フロント degraded 表示の材料（Phase 2 で UI 連携） |

## 5. Phase 1: 持続型 Full-Duplex Session Runtime

### 5.1 RealtimeRuntimePort

**配置:** `backend/app/ai_pipeline/runtime/`

```python
# プロトタイプ由来の決定形状
class RealtimeRuntimePort(Protocol):
    async def open_session(self, context: SessionContext) -> None: ...
    async def append_audio(self, pcm: bytes) -> None: ...
    async def commit_turn(self, utterance_id: str) -> None: ...
    async def interrupt(self, generation_id: int) -> None: ...
    def events(self) -> AsyncIterator[RuntimeEvent]: ...
    async def close_session(self) -> None: ...
```

実装:

| 実装 | 役割 |
|------|------|
| `PerUtteranceRuntime` | 現行互換。発話ごとに connect/disconnect（既定） |
| `NativePersistentRuntime` | 会議中は Provider WebSocket を維持 |

TEN Adapter は本設計の対象外（将来 Phase 3）。ただし Port の背後に隠せる形にしておく。

### 5.2 セッションキーとライフサイクル

```text
session_key = room_id + speaker_id + target_language + provider
```

| イベント | 動作 |
|----------|------|
| 会議開始 / 最初の該当発話 | `open_session` |
| 発話セグメント確定 | `append_audio`（セグメント PCM）→ `commit_turn(utterance_id)` |
| 同一話者の次発話開始（barge-in） | `generation_id` 更新 → `interrupt(旧id)` → 旧音声 flush |
| Provider 切断 | 自動再接続。再接続中は聞く主線停止・読む主線継続 |
| 参加者退室 / 会議終了 | `close_session` |

現行はセグメント単位処理のため、**barge-in の定義**は次とする。

> 同一話者の次発話セグメントが確定した時点で、前発話の未配信翻訳音声・未完了 hearing タスクを cancel し、旧 `generation_id` の再生を禁止する。

ストリーミング中のユーザー割込み（Server VAD 連動）は、持続ランタイムが Provider の入力文字起こし開始イベントを受けられるようになった段階で拡張する（本 Phase の必須完了条件には含め、測定可能な停止時間目標を置く）。

### 5.3 generation_id 規約

| 項目 | 規約 |
|------|------|
| 発行単位 | 話者セッション内で単調増加する整数 |
| 付与対象 | hearing 生成（翻訳音声・hearing delta） |
| cancel | 新 generation 発行時に旧 generation のタスクを cancel |
| flush | Publisher 側の当該 (speaker, lang) の未再生バッファを破棄（実装は lock 区間で世代チェック） |
| 再生禁止 | `generation_id` 不一致の音声フレームは capture しない |

`utterance_id` は発話セグメントごとに UUID を発行し、字幕 `id` / DB `TranscriptSegment` と追跡可能にする（既存 `generate_subtitle_id` と整合）。

`GenerationTracker` は純ロジックとし、単体テスト可能にする。

### 5.4 再接続とフォールバック

```text
Provider 切断
  → reconnect（指数バックオフ、上限回数あり）
  → 再接続中: hearing 停止、reading 継続、runtime=degraded イベント
  → 上限超過: realtime_runtime を一時的に per_utterance 相当へ切り戻し
  → 回復後: persistent へ復帰を試みる（設定で無効化可）
```

LiveKit Track 受信ループ（`_ingest`）内で Provider を await してはならない（既存の worker 委譲を維持）。

### 5.5 設定フラグと段階移行

`backend/app/config.py` の `Settings` に追加する方針（**`.env` / `.env.example` は本作業では編集しない**。追加キーは下記をユーザー確認後に反映）。

| 環境変数キー | Settings フィールド | 既定 | 意味 |
|--------------|---------------------|------|------|
| `REALTIME_RUNTIME` | `realtime_runtime` | `per_utterance` | `per_utterance` / `native_persistent` |
| `REALTIME_RECONNECT_MAX` | `realtime_reconnect_max` | `3` | 再接続試行上限 |
| `INGRESS_SOFT_LIMIT` | `ingress_soft_limit` | `8` | Phase 0 soft |
| `INGRESS_HARD_LIMIT` | `ingress_hard_limit` | `64` | Phase 0 hard |
| `INGRESS_MAX_AGE_MS` | `ingress_max_age_ms` | `30000` | Phase 0 max age |

段階移行:

1. 既定 `per_utterance` のまま Ingress（Phase 0）を本番投入
2. ステージングで `native_persistent` を有効化して比較
3. 割込み・再接続・メモリが基準を満たしたら既定を切り替え

## 6. Phase 2: QoE Control Plane

### 6.1 統一イベントスキーマ

既存字幕ペイロード（`type/id/seq/speaker_id/...`）を破壊しない **加算的拡張**。

```json
{
  "schema_version": 1,
  "event_id": "uuid",
  "type": "subtitle",
  "room_id": "room-001",
  "speaker_id": "user-a",
  "utterance_id": "utt-001",
  "generation_id": 4,
  "sequence_id": 120,
  "revision": 0,
  "provider": "openai_realtime",
  "runtime": "native",
  "trace_id": "room-001:user-a:120",
  "timestamp_ms": 1785000000000
}
```

| フィールド | 必須 | 備考 |
|------------|------|------|
| `schema_version` | 全イベント | 現在は `1`。未知版はフロントが安全に無視 |
| `event_id` | 推奨 | 冪等・追跡 |
| `utterance_id` | 字幕・音声系 | 発話単位 |
| `generation_id` | hearing 系 | 整数 |
| `sequence_id` | 字幕 | 既存 `seq` と同一意味。互換のため当面 `seq` も併存可 |
| `revision` | interim | 同一 utterance 内で単調増加 |
| `runtime` | AI 系 | `native`（将来 `ten`） |
| `trace_id` | 推奨 | `room:speaker:seq` 形式 |

`subtitle_interim` は Phase 2 で初めてバックエンドから送出する。

- 同一 `id`（utterance）に対し `revision` を増やして更新
- `subtitle`（final）到着でフロントの interim を削除（既存 `removeInterimSubtitle` を利用）

### 6.2 Media Plane 指標の収集経路

```text
Browser RTCPeerConnection.getStats()
  → useLiveKit が周期サンプリング（例: 2s）
  → 必要最小限の集約（RTT, jitter, packetsLost, concealedSamples,
     availableOutgoingBitrate, ICE candidate type, TURN 利用有無）
  → DataChannel または既存 preference/属性経路で Agent / 集約API へ
  → QoEStateMachine へ入力
```

制約:

- 会議本文・生音声を診断ログに含めない
- Token / API Key をログに出さない
- 送信頻度とペイロードサイズに上限を設ける（境界条件章）

### 6.3 QoEStateMachine（新規シーム）

**配置:** `backend/app/ai_pipeline/qoe.py`（純ロジック）

| 入力条件 | 遷移 | 出力動作 |
|----------|------|----------|
| packet loss > 5% | `media_degraded` | 翻訳音声停止 → 原声 + 字幕 |
| hearing P95 超過（既存 HybridQoSMonitor） | `hearing_degraded` | Mode A 停止 → Mode B |
| Provider 切断 / 再接続中 | `provider_recovering` | 字幕のみ |
| soft_limit 超過（Ingress） | `queue_overload` | partial 停止（Phase 2）+ Mode A 停止 + final 優先 |
| 上記が解消しクールダウン経過 | `healthy` | 段階的に Mode A / 翻訳音声を復帰 |

既存 `HybridQoSMonitor.hearing_degraded`（`qos.py` L192-210）と矛盾させず、QoE は Media + Queue + Provider を束ねる上位判定とする。

### 6.4 フロント状態モデル拡張

| 現状 | 拡張 |
|------|------|
| `ConnectionStatus`: disconnected / connecting / connected / reconnecting（`roomStore.ts` L14） | 接続系は維持 |
| QoS は `qosWarnings` + `shouldFallbackToSubtitle` 表示のみ | `RoomMediaState`: `healthy` / `degraded` / `interrupted` を追加 |
| interim 受信ハンドラのみ（`useLiveKit.ts` L339-346） | `revision` 更新・未知 `schema_version` 無視・final で interim 削除を正式化 |
| autoplay 失敗はエラー文字列のみ | degraded 時と同様、ユーザー操作で再試行可能な案内を維持 |

UI は「過負荷・品質低下・割込み」を区別して短文表示する。listening / translating / playing の細粒度は必須としない（ある場合は Room 内ステータスとして任意拡張）。

## 7. 境界条件

### 7.1 Phase 0（Ingress）

| 項目 | 境界 | 異常時 |
|------|------|--------|
| soft_limit | 1〜hard_limit-1、既定 8 | 設定不正時は既定値へフォールバックし warning ログ |
| hard_limit | soft+1〜256、既定 64 | 同上 |
| max_age_ms | 1000〜120000、既定 30000 | 同上 |
| 空セグメント | 受理しない | enqueue 前に破棄（計上不要） |
| 終端シグナル `None` | worker 停止用。limit 対象外 | 必ず put できる経路を残す |
| 同時話者数 | 会議室の参加者上限に従う | 話者ごとに独立 Ingress |
| soft 超過中の新規発話 | accept_degraded（破棄しない） | hearing のみ抑止 |
| hard 超過 | drop_hard + final_dropped++ | error ログ必須 |
| 欠落 0 件保証の範囲 | soft 運用時 | hard/aged は観測付き破棄 |

### 7.2 Phase 1（Runtime）

| 項目 | 境界 | 異常時 |
|------|------|--------|
| session_key 構成要素 | いずれも非空 | open 拒否 |
| 同時持続セッション数 | 話者×目標言語×provider。会議あたり上限を設定（推奨: 目標言語数×話者数、既定上限 32） | 超過時は該当言語を reading のみへ |
| generation_id | 1 から単調増加、64bit 以内 | wrap させない。セッション再 open でリセット可 |
| 再接続回数 | 既定上限 3 | per_utterance へ切り戻し |
| 再接続バックオフ | 例: 0.5s, 1s, 2s | 上限で停止 |
| barge-in 停止目標 | 旧音声停止 ≤ 300ms（測定は interrupt 呼出〜最終 capture 拒否） | 超過はメトリクス警告 |
| `_ingest` 内の Provider await | 禁止 | 違反は設計欠陥 |

### 7.3 Phase 2（QoE / イベント）

| 項目 | 境界 | 異常時 |
|------|------|--------|
| schema_version | 現状 1 のみ受理 | 未知は無視（クラッシュ禁止） |
| Stats 送信周期 | 1〜10s、推奨 2s | 欠損時は前回値を保持せず「不明」扱い（誤縮退を避ける） |
| packet loss 閾値 | 5% で翻訳音声停止 | ヒステリシス（例: 3% 未満で復帰）を推奨 |
| interim revision | 同一 utterance 内で単調増加 | 逆転は無視 |
| 診断ログ | 本文・Token・API Key 禁止 | マスク必須 |
| フロント字幕保持 | 最新 50 件（既存 `roomStore.ts` L133） | 変更しない |

## 8. 制約条件

### 8.1 アーキテクチャ制約

- WebRTC / LiveKit を Media Plane として維持する（Agora 置換しない）。
- 音声フォーク地点は Gateway（`LiveKitAgent`）に限定する。
- Mode A（hearing）と Mode B（reading）を内部結合しない。
- 正式記録は Mode B を基準とする。
- クライアント配信は OutputSink / Publisher 経由に限定する。
- 持続ランタイムは `RealtimeRuntimePort` の背後に隠蔽する（呼び出し側が Provider SDK に直接依存しない）。

### 8.2 性能制約

- LiveKit Track 受信処理内で Provider を待たない。
- すべての Queue に上限を設定する。
- soft_limit 範囲で final を黙って破棄しない。
- 古い音声 / セグメントに max_age を設定する。
- `generation_id` 不一致の音声を再生しない。
- 同時翻訳言語数に上限を設定する（会議ポリシー / セッション上限）。

### 8.3 セキュリティ制約

- API Key / LiveKit Token をログへ出力しない。
- 診断ログに会議本文を含めない。
- Room / Tenant / Participant の認可を維持する。
- 本番は HTTPS、WSS、TURN/TLS を利用する。

### 8.4 互換性制約

- 既存字幕フィールドを削除・改名しない（加算のみ）。
- 既定 `realtime_runtime=per_utterance` で現行挙動を維持する。
- フロントは未知フィールド・未知 schema_version を無視できること。

### 8.5 ライセンス制約（本設計の対象外だが継承）

TEN Framework 採用は本設計に含めない。将来 PoC する場合は、元ドキュメント §13.4 の法務確認を完了するまで本番依存にしない。

## 10. テスト戦略

### 10.1 良いテストの定義

- 外部から観測できる振る舞いのみを検証する（破棄するか、縮退するか、旧 generation を再生しないか）。
- 実装詳細（内部辞書名など）に固定しない。
- I/O は既存どおり Fake / monkeypatch / コンストラクタ注入で置換する。

### 10.2 既存シーム（流用）

| シーム | 用途 |
|--------|------|
| `HybridOrchestrator(hearing_fn=, reading_fn=, monitor=)` | 主線差し替え |
| `SegmentProcessor(orchestrator=, sequencer=, detect_fn=)` | 収束差し替え |
| `OutputSink` / `_FakeSink` | 配信差し替え |
| `LiveKitAgent(processor=, ..., room=)` | rtc 配線差し替え |

### 10.3 新規シーム（純ロジック）

| シーム | テストファイル（予定） |
|--------|------------------------|
| `SegmentIngress` | `backend/tests/test_segment_ingress.py` |
| `GenerationTracker` + Runtime 契約 | `backend/tests/test_realtime_runtime.py` |
| `QoEStateMachine` | `backend/tests/test_qoe.py` |

### 10.4 既存テストの拡張

| 既存 | 変更方針 |
|------|----------|
| `test_agent_queue.py` | 「満杯で最古破棄」期待を廃止。soft では破棄せず degraded、hard では `final_dropped` 計上を検証 |
| `test_orchestrator.py` | overload 時 hearing 抑止、イベント加算フィールド |
| `test_qos.py` | Ingress / Media 連動がある場合のみ拡張 |
| `test_livekit_sink.py` | generation 不一致で capture しない |

### 10.5 新規テストケース（必須シナリオ）

**Phase 0**

1. depth &lt; soft → accept、drop 0
2. soft ≤ depth &lt; hard → accept_degraded、drop 0、overload true
3. depth ≥ hard → drop_hard、final_dropped 増加、ログ理由あり
4. oldest_age &gt; max_age → drop_aged、計上あり
5. soft 超過中も reading 字幕は処理継続（orchestrator 連携）

**Phase 1**

1. 同一 session_key で接続が使い回される（connect 回数）
2. commit_turn 後に events が得られる
3. interrupt 後、旧 generation の音声が配信されない
4. 再接続成功 / 上限超過で per_utterance 相当へフォールバック
5. `_ingest` が Provider 待ちでブロックされない（worker 分離の回帰）

**Phase 2**

1. 未知 schema_version をフロントが無視
2. interim revision 更新と final での削除
3. packet loss &gt; 5% で翻訳音声停止判定
4. 条件解除 + クールダウンで healthy 復帰
5. Stats ペイロードに本文・秘密情報が含まれない

Prior art: `test_agent_queue.py`, `test_orchestrator.py`, `test_qos.py`, `test_mode_router.py`, `test_segmenter.py`。

## 14. 最終方針（本設計の要約）

> LiveKit / Mode Router / OutputSink は維持する。  
> まず確定発話を失わない Ingress を入れる。  
> 次に Native 持続ランタイムと generation 管理で Full-Duplex を整える。  
> その上で Media+AI の QoE で自動縮退する。  
> TEN は比較基線ができた後の別設計とする。
