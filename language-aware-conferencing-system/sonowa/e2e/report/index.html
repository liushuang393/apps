📖 用語ガイド（はじめて見る人はここから）
  • 合格 / 不合格 — 「画面を自動解析できた」「テストの目印が壊れていない」「P1 を定義している場合は 1 件以上自動テスト化されている」の 3 条件を全部満たすと合格（P1 未定義の app は 3 条件目を免除）。
  • P1 — 最重要の業務シナリオ。失敗すると売上・法令・データの正しさに直撃するもの。
  • P1 保護率 — 最重要シナリオのうち、自動テストで守られている割合。
  • blocked — 仕様の確認待ちで止まっているテスト。放置すると守られていない業務が残る。
  • testid — テストが画面の部品（ボタン等）を見つけるための目印。drift はその目印のズレ＝テストが壊れている数（0 が正常）。
  • 占位（プレースホルダ） — 画面が開くことしか確認していない形だけのテスト。数字は増えるが業務は守られない。
  • screens — ツールが自動解析できた画面の数。frontend を持たない API 専用 app は 0 でも、API route が検出できていれば解析成功扱い。
  • 詳しい読み方: 業務カバレッジの意味づけ (13) ・ このレポートの仕組み・更新方法 (README §5-2) ・ ドキュメント一覧

同じ診断を 2 回実行して同じ結果になるかの確認（テスト自体の安定性チェック）。完全一致なら OK。
